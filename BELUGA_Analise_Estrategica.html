1. Sumário Executivo

O BELUGA é uma plataforma SPA (Single Page Application) de suporte acadêmico voltada para estudantes universitários, que combina quiz diagnóstico, plano de estudos personalizado por IA, gamificação (XP, conquistas, ranking), comunidade social (Feed e Fórum) e assistente virtual. O frontend está bem construído, com design dark mode consistente, componentes reutilizáveis e código organizado em módulos ES.

Estado atual do produto (honesto) O BELUGA é um protótipo de alta fidelidade. Visualmente impressionante e bem estruturado — mas 100% frontend com dados mock. Não há backend, não há autenticação real, não há persistência. Nenhuma interação do usuário sobrevive a um F5.

O que o BELUGA faz bem hoje

  • Design visual coerente e profissional (dark mode, sistema de cores, tipografia)
  • Arquitetura frontend limpa — módulos ES, roteamento por hash, separação de responsabilidades
  • Gamificação bem executada (XP, níveis, streaks, ranking, conquistas com troféu)
  • Modal de perfil de usuário com dados ricos (sessão anterior)
  • Sistema de notificações com filtros, busca e criação de lembretes
  • Plano de estudos com trilhas detalhadas e navegação por dia

O que bloqueia o lançamento

  • Sem backend: todo dado é mock — cadastro, quiz, plano, posts, conquistas
  • Beluginha IA é fake: retorna frases aleatórias de um array; não é IA
  • Landing page fraca: não comunica o diferencial real para um universitário
  • Ciclo core quebrado: Quiz → Plano existe visualmente, mas não é real
Veredicto de lançamento Com 8–12 semanas focadas, o BELUGA pode ter um beta funcional com dados reais, suficiente para validação com usuários e apresentação para investidores anjo. O produto tem diferencial — o problema é execução, não visão.

2. Análise Detalhada de Telas

Cada tela foi analisada diretamente do código-fonte (JS + CSS). A análise considera: estado atual de implementação, problemas identificados com severidade, pontos positivos e solução recomendada.

2.1 Landing Page CRÍTICA

Estado atual

A landing é composta por um header com logo + nav (Funcionalidades, Preço, Contato), uma seção hero com headline e imagem do mascote animado (float animation), e um strip horizontal de cards de funcionalidades intercalados com depoimentos falsos.

Diagnóstico: a landing page é o maior problema do BELUGA hoje É a primeira coisa que um investidor, parceiro ou usuário vai ver. Atualmente não demonstra diferencial, não mostra o produto e não convence ninguém a se cadastrar.

Problemas identificados

ProblemaSeveridadeDetalhe técnico
Headline genérica Alta "Organize seus estudos de forma INTELIGENTE" — poderia ser de qualquer app. Não fala com universitário, não menciona IA, não menciona comunidade, não menciona gamificação.
Nav com links quebrados Alta O menu tem "Preço" e "Contato" que disparam scrollIntoView para IDs #preco e #contato que não existem no HTML — os links não funcionam.
Sem preview do produto Alta Nenhum screenshot, mockup ou vídeo do dashboard, quiz ou plano de estudos. O usuário não sabe o que vai encontrar ao se cadastrar.
Beluginha IA ignorada Alta O maior diferencial do produto não aparece no hero nem nas features da landing. "Planejamento com IA" é mencionado num card de 180px — sem destaque.
Zero prova social Alta Avatares de pravatar.cc (externo), nomes fictícios sem credibilidade. Sem número de usuários, sem universidades parceiras, sem nota de avaliação.
Travado em 100vh Média O CSS força overflow: hidden; height: 100vh — impossível adicionar novas seções (preços, screenshots, FAQ) sem redesign de layout.
CTA único sem alternativa Média Só "COMECE AGORA" — usuário que quer saber mais não tem opção além de se cadastrar.

Solução recomendada

  • Novo hero com tagline específica: "O assistente de estudos que entende o universitário brasileiro — com IA que monta seu plano, comunidade que te apoia e gamificação que te mantém no ritmo."
  • Seção de preview do produto: screenshot real do dashboard com legenda
  • Seção de features com hierarquia clara: IA no topo, gamificação em segundo
  • Seção de preços: Free tier + plano Premium (preparar para monetização)
  • Seção de depoimentos reais: coletar de beta users
  • Remover restrição de 100vh: permitir scroll normal para mais conteúdo
  • Adicionar CTA secundário: "Ver como funciona" que ancora para demo
2.2 Dashboard BOM — com ressalvas

Estado atual

Hub central do aluno. Exibe: header com avatar + nível + barra de XP, progress das matérias com barras animadas, alerta de matéria crítica, missões ativas com progresso, ranking semanal top 3, e cards de ações rápidas.

Ponto forte: É a tela mais impressionante do app para uma demo. A animação de entrada das barras, o alerta contextual de matéria crítica e a gamificação visual estão muito bem executados.

Problemas identificados

ProblemaSeveridade
Tudo hardcoded: nome Jimmy, nível 7, XP 3240, matérias fixasAlta
Ranking com apenas 3 pessoas — parece vazioMédia
Sem indicador de streak ativo (ex: "7 dias seguidos")Média
Quick Actions sempre iguais — não adapta ao contexto do usuárioBaixa
Data de última visita não mostradaBaixa

Solução

Dados reais via backend (Supabase ou similar). Adicionar streak counter no header. Expandir ranking para top 10. Quick Actions dinâmicos baseados no último acesso e nas matérias com menor progresso.

2.3 Quiz MELHORADO — problemas pendentes

Estado atual

Quiz diagnóstico que gera perguntas baseadas nas disciplinas da Matriz Curricular. Após melhorias recentes: sem auto-advance, botão "Próxima →" funcional, botão de finalizar visível apenas na última pergunta. Sidebar de progresso com tiles clicáveis.

Problemas pendentes

ProblemaSeveridadeDetalhe
Sem feedback ao finalizar Alta Ao clicar "Finalizar", vai direto para o Plano sem mostrar resultado: % de acertos, quais matérias o usuário vai melhor/pior, XP ganho.
Banco de questões estático Alta 6 categorias hardcoded (algoritmos, sistemas, design, inovacao, limite, trabalho). Disciplinas fora desse conjunto caem em perguntas genéricas inúteis.
Quiz não muda o plano de verdade Alta O resultado do quiz não é lido pelo Plano de Estudos. O plano sempre exibe os mesmos dados hardcoded independente do quiz.
Sem modo revisão de erros Média Após finalizar, não é possível ver quais questões errou nem a resposta correta.
Nenhuma dificuldade adaptativa Baixa Questões sempre no mesmo nível — não fica mais difícil conforme o usuário acerta.

Solução

  • Adicionar tela de resultado pós-quiz: % de acertos por matéria, XP ganho, recomendações
  • Salvar resultado no backend e passá-lo como input para geração do plano
  • Expandir banco de questões para as disciplinas mais comuns dos cursos universitários brasileiros
  • A Beluginha IA pode gerar questões dinamicamente no futuro
2.4 Plano de Estudos CONCEITO EXCELENTE — execução pendente

Estado atual

Uma das telas mais completas e bem executadas do app. Possui navegação por dia da semana (tabs), barra de resumo diária, trilhas por matéria com progress ring circular, tópicos individuais com status (feito/aberto), recomendação de IA por tópico, tempo estimado e card de descanso/revisão livre.

Ponto forte: A UX da trilha de conhecimento (rings de progresso, tópicos com CTA, tempo estimado) está acima da média do mercado. Visualmente é diferenciado.
Problema crítico de honestidade com o usuário: O subtítulo diz "Trilha de conhecimento gerada pela Belugin IA" — mas é um array hardcoded. Isso é falsa publicidade. Precisa ser corrigido antes de qualquer apresentação pública.

Problemas

ProblemaSeveridade
"Gerada pela Belugin IA" — mentira técnica, é dado estáticoAlta
Marcar tópico como concluído não persiste (F5 apaga tudo)Alta
Plano não muda com base no resultado do quiz realAlta
Disciplinas hardcoded — não usa a Matriz Curricular do usuárioAlta
"Refazer Plano de Estudos" vai pro quiz mas não reseta o planoMédia

Solução

  • Backend: salvar progresso de tópicos por usuário
  • Gerar plano com base no resultado do quiz — algoritmo simples: matérias com menor % de acerto → nível "Atenção", maior carga horária
  • Integrar com Matriz Curricular para usar as disciplinas reais do usuário
  • Quando Beluginha IA real for implementada: ela gera a ordem e recomendações dos tópicos
2.5 Matriz Curricular FUNCIONAL — falta integração

Estado atual

Permite ao usuário adicionar disciplinas do seu curso. Usa localStorage para persistência local. A função getDisciplines() é importada pelo Quiz e pelo Plano.

Problemas

ProblemaSeveridade
localStorage sem sync com backend — perde ao limpar browserAlta
Quiz usa disciplinas mas plano ignora — inconsistênciaAlta
Sem validação de duplicatas ou limite de disciplinasBaixa

Solução

Manter localStorage como fallback temporário. Backend: tabela user_disciplines sincronizada. Usar as disciplinas para personalizar quiz, plano e recomendações da Beluginha.

2.6 Aulas PLACEHOLDER — sem conteúdo real

Estado atual

Listagem de vídeo-aulas com thumbnails, duração e player simulado. Tudo mock.

Atenção estratégica: Conteúdo é o core de qualquer edtech. Sem aulas reais, o produto não entrega valor acadêmico direto. Esta é a segunda prioridade após o backend.

Solução rápida e viável

  • Curto prazo: Curar playlist do YouTube com vídeos de qualidade por disciplina e embeddá-los — custo zero
  • Médio prazo: Integrar YouTube Data API para busca dinâmica por disciplina/tópico
  • Longo prazo: Produção própria ou parcerias com professores universitários (ex: modelo Khan Academy)
2.7 Biblioteca SIMPLES — pode ser diferenciador

Estado atual

Listagem de materiais de estudo (PDFs, artigos) com mock data.

Solução

  • Curar PDFs e artigos open access (SciELO, arXiv, repositórios universitários) por disciplina
  • Beluginha IA pode recomendar materiais baseados no desempenho do usuário — diferenciador forte
  • Permitir que usuários façam upload de apostilas (feature social/colaborativa)

Ponto forte: O Feed é uma das páginas mais bem executadas. O modal de perfil integrado (com XP, conquistas e atividade recente do usuário) é um diferencial real — nenhum concorrente tem isso integrado ao feed.

Problemas

ProblemaSeveridade

2.9 Fórum BOA EXECUÇÃO — falta backend

Diferencial importante

O Fórum tem "Monitores" (usuários com badge especial). Isso cria uma hierarquia social acadêmica — monitores reais das universidades podem usar o BELUGA para tirar dúvidas, tornando o conteúdo mais confiável.

2.10 Conquistas DESTAQUE POSITIVO

Destaque: O modal de compartilhamento de conquistas é uma feature de crescimento viral embutida. Se o usuário compartilhar no X ou no Feed com o nome BELUGA, gera marketing orgânico. Isso precisa funcionar de verdade.

2.13 Beluginha IA CRÍTICA — o maior diferencial está vazio

Estado atual

Botão flutuante (FAB) com imagem do mascote, presente em todas as telas privadas. Ao clicar, abre um chat com cabeçalho "Belugin - IA | Assistente acadêmico | Online". O usuário digita uma mensagem e recebe uma resposta após 0,9–1,6 segundos de "digitando..."

O problema central:
As respostas são escolhidas aleatoriamente de um array de 8 frases fixas (MOCK_RESPONSES). A Beluginha não lê o que o usuário escreveu, não tem memória, não acessa dados do app. É um chatbot de fachada.

Exemplo: se o usuário escrever "Qual a derivada de x²?", a Beluginha responde "Encontrei uma dúvida parecida no Fórum. Posso te direcionar para ela." — aleatoriamente, sem qualquer relação.

Por que isso é o problema #1 do produto

O nome do assistente aparece em toda a comunicação do produto: "Assistente acadêmico com IA" (hero da landing), "Planejamento com IA" (strip), "Trilha de conhecimento gerada pela Belugin IA" (plano de estudos), "IA recomenda" (tags nos tópicos do plano). O produto inteiro é vendido em cima de uma IA que não existe.

Solução técnica concreta

  • API: Claude API (Anthropic) ou OpenAI GPT-4o — ambas têm SDK JavaScript simples
  • Contexto mínimo para a 1ª versão: enviar junto com a mensagem: nome do usuário, lista de disciplinas, última matéria acessada, resultado do último quiz (% por disciplina)
  • Custo estimado: com Claude Haiku (~$0.25/1M tokens), uma conversa de 10 trocas custa menos de $0.01 — viável para beta
  • Casos de uso para implementar em ordem:
    1. Responder dúvidas sobre conteúdo das disciplinas
    2. Gerar o plano de estudos real baseado no resultado do quiz
    3. Dar feedback nas respostas erradas do quiz
    4. Recomendar materiais da biblioteca por tópico
Oportunidade de diferenciação máxima: nenhum concorrente brasileiro tem uma IA académica real integrada ao plano de estudos. Se a Beluginha funcionar de verdade, o BELUGA para de ser "mais um app de estudos" e se torna uma categoria própria.

4. Roadmap de Desenvolvimento

Roadmap dividido em fases com objetivos claros, entregáveis mensuráveis e critérios de sucesso. Cada fase deve ser concluída antes de iniciar a próxima.

Fase 0 — Fundação & Infraestrutura (Semanas 1–4)

Objetivo: Criar a base técnica sem a qual nenhuma feature funciona em produção.

  • Escolher e configurar backend: Supabase (PostgreSQL + Auth + Storage + Realtime) — gratuito para volume de beta, setup em horas, não dias
  • Autenticação real: e-mail + senha + Google OAuth (Supabase Auth)
  • Schema inicial de banco: users, user_disciplines, quiz_sessions, quiz_answers
  • Deploy: Vercel (frontend) + Supabase (backend) — custo zero até escala
  • Variáveis de ambiente: separar API keys do código-fonte

Critério de sucesso: Usuário consegue se cadastrar, logar e ter sua sessão persistida entre recargas.

Fase 1 — Ciclo Core do Produto (Semanas 5–8)

Objetivo: O ciclo Matriz → Quiz → Plano funcionar de ponta a ponta com dados reais.

  • Matriz Curricular: sincronizar com Supabase
  • Quiz: salvar respostas no banco, calcular % de acerto por disciplina
  • Tela de resultado pós-quiz: acertos, pontos fracos, XP ganho
  • Plano de Estudos: gerado dinamicamente com base no resultado do quiz
  • Progresso de tópicos: persistência de itens marcados como concluídos
  • Beluginha IA (v1): integrar Claude Haiku com contexto básico do usuário — responde dúvidas de conteúdo e explica erros do quiz

Critério de sucesso: Usuário faz quiz, vê resultado, recebe plano personalizado, estuda, marca tópicos e conversa com a Beluginha sobre dúvidas — tudo persistido.

Fase 2 — Comunidade & Gamificação Real (Semanas 9–12)

Objetivo: Ativar o motor de retenção e crescimento viral.

  • Feed: backend para posts, likes, comentários com moderação básica
  • Fórum: perguntas e respostas com votação real
  • Sistema de XP real: eventos que geram XP (quiz feito, tópico concluído, post no feed, resposta no fórum)
  • Conquistas: triggers automáticos (completou 5 quizzes, 7 dias de streak, etc.)
  • Ranking: semanal por XP, em tempo real com Supabase Realtime
  • Notificações: Web Push API para lembretes de estudo

Critério de sucesso: Usuário volta ao app naturalmente por notificação, vê seu XP crescer, interage com a comunidade.

Fase 3 — Conteúdo & Biblioteca (Semanas 13–14)

Objetivo: Entregar valor educacional direto.

  • Aulas: curar 50–100 vídeos do YouTube por disciplina (as 10 mais comuns nos cursos-alvo)
  • Integrar YouTube Data API para busca dinâmica
  • Biblioteca: curar PDFs open access + links para materiais relevantes
  • Beluginha IA: recomendar vídeos e materiais baseada no histórico do usuário

Fase 4 — Landing & Go-to-Market (Semanas 15–16)

Objetivo: Estar pronto para aquisição de usuários e apresentação para investidores.

  • Redesign da landing page com screenshots reais do app
  • Tagline específica para universitário brasileiro
  • Seção de preços: Free tier + Premium (definir o que vai no pago)
  • Métricas do beta: usuários, sessões, retenção D7/D30
  • SEO básico: meta tags, sitemap, Open Graph
  • PWA: instalar no celular sem loja de app

Critério de sucesso: 100 usuários beta ativos, NPS > 50, deck de pitch com dados reais.
